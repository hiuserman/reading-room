# 共同本棚・読書共有アプリ 要件定義
版 0.5 ／ 2026-11-17 ／ 提出期限 2026-12-08

## 目的
仲のよい人と本棚を共有し、表紙・タイトル、投稿時刻、現在ページ、本人のひとことで「今これを読んでいる」を伝える。過去の本は全冊ライブラリに残す。Goは本人、フロントはCodexが担当する。

## 提出用の基本機能
| 機能 | 受入条件 |
| --- | --- |
| 本の登録・一覧 | タイトル・著者を手入力で登録し、再読込後も保存済みの本が見える |
| 読書投稿 | 本を選び、状態・現在ページ・ひとことを記録する。時刻はサーバーの投稿日時 |
| 状態 | reading＝読書中、paused＝サボり中、finished＝読了。本人が明示的に選び、放置日数で自動判定しない |
| ページ | 任意の0以上の整数。未入力はnull。総ページ数や進捗率は必須にしない |
| ひとこと | 投稿者本人の200文字以内の感想。空でも進捗だけ記録できる。返信欄は作らない |
| ネタバレ | 投稿者が指定。本文は初期非表示で、ボタンで表示・再度隠せる。隠している間はDOMに本文を置かない |
| みんなの近況 | 新しい順に直近6件。表紙がなければタイトル・著者を使ったカードで表示 |
| 本棚・全冊ライブラリ | 独立した「本」タブで全冊のタイトル・著者・追加者・本人の読了実績を確認する。各人の段は提出用UIから外す。一覧の表示制限でDBデータを消さない |
| 共同利用 | ユーザーごとに状態を分離。公開する場合は認証と参加権限チェックを必須とする |

現在ページは以前の対象外から変更し、初期版に採用。未記録はReadingRecordsなしで扱う。過去案のunreadは提出用の選択肢から外す。読書時間の計測は引き続き対象外。

## 後回し
写真アップロード、キャラクター、返信、リアクション、バーコード、自由配置、アーカイブ・脱退の管理UI、読書時間推定。
ISBN手入力検索・表紙取得は基本動作完成後に追加する。外部検索が未完成でも手入力で提出デモを成立させる。認証サービス・招待方法・AWS公開が提出必須かは未確定。

## API計画（未実装部分を含む）
実装済みの契約は api.yaml。以下を完成済みと扱わない。
| Method | Endpoint | 用途 |
| --- | --- | --- |
| GET / POST | /api/shelves | 参加棚一覧・作成 |
| GET / POST | /api/shelves/{shelfId}/books | 本の一覧・登録 |
| GET / POST | /api/shelves/{shelfId}/posts | 投稿の取得・作成 |
| GET | /api/shelves/{shelfId}/reading | 本人・メンバーの最新読書状態 |
| GET | /api/books/search?isbn=... | 後続のISBN検索 |

投稿入力は bookId, status, currentPage, comment, containsSpoiler。userId・日時はサーバーで決定する。POST成功時は作成した投稿と最新状態を201で返す案。投稿と最新状態を同時保存し、本文の再送は同じIdempotency-Keyで重複させない。expectedVersionで競合を検出する。
一覧はlimitとcursor。投稿は既定6/最大30、本・最新状態は既定30/最大100。空の検索結果と読み取り終端を区別する。コメントを含む検索プレビュー・通知は初期版では作らない。

## 提出までの順序
1. 登録の入力検証・日時・一覧GET接続・CORSを整える。
2. 投稿と最新状態の保存APIを実装し、フロントを実データへ接続。
3. メンバー別表示と権限を確認。公開する場合は認証・AWS配備。
4. 12/2〜12/5に通し確認、12/6〜12/7を修正・提出準備に使う。

## 完了確認
- 2冊登録して再読込・DB再起動後も残る。
- 120ページで投稿後、180ページに更新しても旧投稿は120のまま。
- Aが読了してもBの状態は変わらない。
- ネタバレ本文が初期状態で読み上げ・検索対象のDOMに出ず、操作で開閉する。
- ページの負数・小数、不正状態、201文字以上はAPIで400。
- 7件目の投稿や7冊目を追加しても古いデータは保存される。
- 非メンバーは閲覧・更新できず、他人名義で投稿できない（公開前必須）。

## 画面方針（2026-11-17改訂）
PCでも幅430pxを上限にしたスマホUIを中央に表示。スマホでは画面幅いっぱいに表示する。
「みんな」は縦に連続する近況カード（時刻・タイトル・進捗・ひとこと）を主役にし、投稿者で絞り込む。
下部の「みんな／記録する／本」で切り替える。入力フォームを常時横に置く構成と、本棚をホームに並べる構成を廃止する。
読書投稿・本のデータ設計と技術構成は維持。素材・名称は独自のものを使用する。
